# 电池模块 RS485 接入说明

本文对应 `MODBUS协议 V3.9`，用于 MiniCollection 通过 EG628 的 RS485 接口读取电池控制器的 SOC、电压、电流、温度等数据，并上传到 mseed 服务器、在控制台显示。

## 1. 接线

电池控制器使用文档中的 **RS485 接口②**，端子定义：

| 端子 | 定义 |
| --- | --- |
| ① | 电源正 |
| ② | D+ |
| ③ | D- |
| ④ | 电源地 / 信号地 |
| ⑤～⑧ | NC |

EG628 侧：

```text
EG628 RS485 A  ─────  电池控制器 ② D+
EG628 RS485 B  ─────  电池控制器 ③ D-
EG628 GND      ─────  电池控制器 ④ GND
```

注意：

- 如果完全无响应，先把 A/B 对调试一次，不同厂家 A/B 标注可能相反。
- 总线两端加 120Ω 终端电阻，中间节点不加。
- 使用双绞线，屏蔽层单端接地。
- 电池控制器和 EG628 必须共地。

串口参数固定为：

```text
9600 8N1，无校验，1 位停止位
```

从站地址默认 `1`，可在控制器参数中修改；本项目通过 `Config.ini [Battery] slave` 配置。

## 2. 协议要点

- 功能码：`03H` 读保持寄存器。
- 数据地址和数据都是 2 字节，先高字节后低字节。
- CRC 先低字节后高字节。
- 帧间静默 > 10ms。
- 一次读取不能跨越地址段：`0100H~0122H` 属于同一段，可以一次读取。

MiniCollection 每次读取 `0x0100` 起 **35 个寄存器**（`0x0023`），覆盖 SOC、电压、电流、温度、负载、太阳能、日统计、累计统计和故障信息。

## 3. 关键寄存器

| PDU 地址 | 含义 | 解析 |
| --- | --- | --- |
| `0100H` | 蓄电池 SOC | 低 8 位，0～100% |
| `0101H` | 蓄电池电压 | ×0.1 V |
| `0102H` | 充电电流 | ×0.01 A |
| `0103H` | 控制器温度 / 蓄电池温度 | 高 8 位控制器，低 8 位电池；b7 符号位，b0～b6 数值 |
| `0104H` | 负载电压 | ×0.1 V |
| `0105H` | 负载电流 | ×0.01 A |
| `0106H` | 负载功率 | W |
| `0107H` | 太阳能板电压 | ×0.1 V |
| `0108H` | 太阳能板电流 | ×0.01 A |
| `0109H` | 充电功率 | W |
| `010AH` | 负载开关 | 0/1 |
| `010BH` | 当天最低电池电压 | ×0.1 V |
| `010CH` | 当天最高电池电压 | ×0.1 V |
| `010DH` | 当天最大充电电流 | ×0.01 A |
| `010EH` | 当天最大放电电流 | ×0.01 A |
| `010FH` | 当天最大充电功率 | W |
| `0110H` | 当天最大放电功率 | W |
| `0111H` | 当天充电安时数 | Ah |
| `0112H` | 当天放电安时数 | Ah |
| `0113H` | 当天发电量 | 文档单位 W |
| `0114H` | 当天用电量 | 文档单位 W |
| `0115H` | 总运行天数 | 天 |
| `0116H` | 蓄电池总过放次数 | 次 |
| `0117H` | 蓄电池总充满次数 | 次 |
| `0118H~0119H` | 蓄电池总充电安时数 | 32 位，高字在前 |
| `011AH~011BH` | 蓄电池总放电安时数 | 32 位，高字在前 |
| `011CH~011DH` | 累计发电量 | 32 位，高字在前 |
| `011EH~011FH` | 累计用电量 | 32 位，高字在前 |
| `0120H` | 负载状态 / 充电状态 | 高字节 b7 负载开关、b0～b6 亮度；低字节充电状态 0～6 |
| `0121H` | 故障/告警高 16 位 | 见协议 4.15 |
| `0122H` | 故障/告警低 16 位 | 见协议 4.15 |
| `E002H` | 蓄电池标称容量 | Ah，启动时读取一次 |
| `E004H` | 蓄电池类型 | 0 自定义，1 开口，2 密封，3 胶体，4 锂电池 |

## 4. 配置

设备上的 `data/Config.ini`：

```ini
[Battery]
enabled=1
mock=0
port=/dev/ttyS1
baud=9600
parity=N
dataBits=8
stopBits=1
slave=1
pollSec=10
uploadSec=60
nominalCapacityAh=0
initialSoc=80
ocvCurve=11.8:0,12.0:20,12.2:40,12.4:60,12.6:80,12.8:100
```

说明：

- `port`：现场用 `ls -l /dev/ttyS*` 和 `dmesg | grep -i tty` 确认；建议使用 `/dev/serial/by-path/...` 稳定路径。
- `nominalCapacityAh=0` 表示从控制器 `E002H` 读取标称容量；读不到时使用 100Ah。
- `initialSoc` 只在控制器 SOC 无效、需要电压回退时使用。
- `ocvCurve` 是 12V 铅酸默认曲线；如果电池是 24V/48V 或锂电池，按说明书修改。
- `mock=1` 时不需要串口，生成模拟数据，便于在 Windows 上联调服务器和控制台。

## 5. 构建

```bash
cmake -B build -G "Visual Studio 16 2019" -A Win32 ^
      -DCMAKE_PREFIX_PATH=C:/Qt/5.15.2/msvc2019
cmake --build build --config Release
```

串口实现按平台区分：

- **Windows**：使用 Qt5 SerialPort，CMake 会自动把 `Qt5SerialPort.dll` 复制到输出目录；
- **EG628 Linux**：使用 POSIX `termios`，**不需要目标 sysroot 安装 Qt5SerialPort**。

因此交叉编译时 `find_package(Qt5 ...)` 不再要求 `Qt5SerialPort`。如果仍然报
`Qt5SerialPortConfig.cmake` 找不到，说明 CMake 缓存还是旧的，删除 `build-eg628-qt6`
重新配置即可。

## 6. 命令行验证

在 EG628 上先用 Python 读通，再启动主程序：

```bash
sudo apt install -y python3-pip
python3 -m pip install minimalmodbus pyserial
```

```python
import minimalmodbus

inst = minimalmodbus.Instrument("/dev/ttyS1", 1, mode=minimalmodbus.MODE_RTU)
inst.serial.baudrate = 9600
inst.serial.bytesize = 8
inst.serial.parity = "N"
inst.serial.stopbits = 1
inst.serial.timeout = 1
inst.clear_buffers_before_each_transaction = True

regs = inst.read_registers(0x0100, 7, 3)
print(regs)
print("SOC", regs[0] & 0xFF)
print("电压", regs[1] * 0.1)
print("充电电流", regs[2] * 0.01)
```

正常应看到类似：

```text
[55, 123, 266, 6945, 122, 200, 240]
SOC 55
电压 12.3
充电电流 2.66
```

如果读不到：

1. 检查 A/B 是否接反；
2. 检查从站地址是否为 1；
3. 检查波特率是否 9600；
4. 检查串口是否被 WukongEdge 或其他程序占用：

```bash
lsof /dev/ttyS1
fuser -v /dev/ttyS1
```

5. 检查终端电阻和共地。

## 7. 服务端接口

### 上传

```http
POST /coalmine/devices/{device_id}/sensors
X-Project-Token: <设备上传令牌>
Content-Type: application/json
```

```json
{
  "samples": [
    {
      "uid": "01-1720000000000-1-battery-main",
      "ts": 1720000000000,
      "sensor_type": "battery",
      "sensor_id": "main",
      "quality": "ok",
      "metrics": {
        "percent": 55,
        "voltage": 12.3,
        "current": 2.66,
        "remaining_ah": 55,
        "battery_temp": 25,
        "load_current": 2.0,
        "load_power": 240,
        "solar_voltage": 14.4,
        "solar_current": 1.5,
        "charge_power": 216,
        "fault_high": 0,
        "fault_low": 0
      }
    }
  ]
}
```

服务端按 `(device_id, uid)` 唯一约束去重，重试不会重复入库。

### 查询最新值

```http
GET /coalmine/devices/{device_id}/sensors/latest
X-Project-Token: <项目令牌>
```

### 查询历史

```http
GET /coalmine/devices/{device_id}/sensors?after_id=0&limit=500
GET /coalmine/devices/{device_id}/sensors?from_ts=...&to_ts=...
```

### 心跳

设备心跳会增加：

```json
"sensors": {
  "battery": {
    "ts": 1720000000000,
    "quality": "ok",
    "percent": 55,
    "voltage": 12.3,
    "current": 2.66,
    "load_current": 2.0,
    "battery_temp": 25,
    "has_fault": false
  }
}
```

控制台设备状态页直接读取 `status.sensors.battery` 即可显示。

## 8. 数据流

```text
RS485 接口②
  -> /dev/ttyS1
  -> ModbusRtuClient（功能码 03）
  -> BatteryService（独立线程）
       -> data/sensors/battery.db（断网缓存）
       -> POST /coalmine/devices/{id}/sensors
       -> batterySnapshot 信号
            -> StatusWindow 显示
            -> DeviceSyncAgent 心跳
  -> 服务器 sensor_samples 表
  -> 控制台 status.sensors / sensors/latest
```

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 串口打不开 | 确认 `port`、权限、是否被 WukongEdge/getty 占用 |
| 无响应 | A/B 对调、从站地址、波特率、共地、终端电阻 |
| Modbus 异常码 02 | 寄存器地址不对，检查起始地址 |
| CRC 错误 | 波特率/校验位不对，或干扰、线缆质量差 |
| SOC 不变化 | 控制器 SOC 本身变化慢；检查是否读到 `0100H` |
| 电压不对 | 确认乘 0.1，不要重复缩放 |
| 上传 401 | `[Upload] token` 与服务器项目令牌不一致 |
| 控制台无电池数据 | 检查心跳是否带 `sensors`，或直接调用 `sensors/latest` |
