# 电量监控操作手册

本手册说明 MiniCollection 电池电量监控的接线、配置、数据含义、服务器接口、控制台日志与告警处理。

适用对象：

- 现场安装/调试人员；
- 设备运维人员；
- 控制台使用人员。

---

## 1. 功能概述

系统链路：

```text
电池控制器 RS485 接口②
    -> EG628 /dev/ttySx
    -> Modbus RTU（9600 8N1，功能码 03）
    -> BatteryService（设备端独立线程）
        -> data/sensors/battery.db（断网缓存）
        -> POST /coalmine/devices/{id}/sensors
        -> 心跳 sensors.battery
    -> 服务器 sensor_samples 表
    -> 控制台设备状态页 + 日志 + 告警
```

采集内容：

- 蓄电池 SOC；
- 蓄电池电压；
- 充电电流；
- 负载电压、负载电流、负载功率；
- 太阳能板电压、电流、充电功率；
- 控制器温度、蓄电池温度；
- 负载开关/亮度、充电状态；
- 故障/告警位；
- 当天和累计统计。

## 2. 设备端接线

电池控制器使用 **RS485 接口②**，端子定义：

| 端子 | 定义 | 接到 EG628 |
| --- | --- | --- |
| ① | 电源正 | 不接（通信不需要） |
| ② | D+ | RS485 A |
| ③ | D- | RS485 B |
| ④ | 电源地/信号地 | RS485 GND 或电源地 |

注意：

- 第 1 脚是电源，不是 RS485 信号，不能接 A/B；
- A/B 如果无响应，对调再试；
- 必须共地；
- 总线两端各 120Ω 终端电阻；
- 使用双绞线，屏蔽层单端接地；
- 如果负载/逆变器直接接电池，不经过控制器 LOAD 输出，控制器测不到放电电流，SOC 只能靠电压估算，精度会下降。

## 3. 确认 EG628 串口

在 EG628 上执行：

```bash
ls -l /dev/ttyS* /dev/ttyUSB* 2>/dev/null
sudo dmesg | grep -iE 'serial|uart|tty|usb'
ls -l /dev/serial/by-path/ 2>/dev/null
sudo cat /proc/tty/driver/serial
```

注意：

- 没有 `/dev/ttyUSB*` 不代表异常，板载 RS485/RS232 是 `/dev/ttyS*`；
- `ttyUSB0~3` 可能是 4G 模块，不要先扫；
- 具体是哪个 `ttyS` 必须用 Modbus 请求确认，不能只看编号。

扫描脚本：

```python
import serial

ports = [
    "/dev/ttyS2", "/dev/ttyS3", "/dev/ttyS4", "/dev/ttyS5",
    "/dev/ttyS6", "/dev/ttyS7", "/dev/ttyS9",
]

for port in ports:
    try:
        ser = serial.Serial(port, 9600, bytesize=8, parity="N",
                            stopbits=1, timeout=0.5)
        ser.reset_input_buffer()
        # 读 0x0100 SOC，从站 1
        ser.write(bytes.fromhex("01 03 01 00 00 01 85 F6"))
        resp = ser.read(7)
        print(port, "->", resp.hex(" "))
        ser.close()
    except Exception as e:
        print(port, "ERROR:", e)
```

返回类似：

```text
/dev/ttyS9 -> 01 03 02 00 2a 39 9b
```

`00 2A` 是 SOC 42%，说明该口是电池控制器。

> 现场实测 EG628 可能是 `/dev/ttyS9`，但不同固件/接线可能不同，必须扫描确认。

## 4. 设备端配置

编辑：

```text
/opt/MiniCollection/data/Config.ini
```

```ini
[Battery]
enabled=1
mock=0
port=/dev/ttyS9
baud=9600
parity=N
dataBits=8
stopBits=1
slave=1
pollSec=10
uploadSec=60
nominalCapacityAh=0
initialSoc=80
ocvCurve=11.8:0,12.0:20,12.2:40,12.4:60,12.6:80,12.8:100
```

说明：

- `port`：实际扫描到的串口；
- `slave`：控制器从站地址，默认 1；
- `nominalCapacityAh=0`：从控制器 `E002` 读取标称容量；
- `initialSoc`：控制器 SOC 无效时的回退值；
- `ocvCurve`：12V 铅酸默认曲线，24V/48V 或锂电池需按说明书修改；
- `mock=1`：不接串口，生成模拟数据，用于联调。

修改后重启：

```bash
sudo systemctl restart minicollection.service
```

查看日志：

```bash
grep -i battery /opt/MiniCollection/Log/*.log | tail -30
```

正常：

```text
Battery|电池串口已打开：/dev/ttyS9，9600 8N1
Battery|电池参数：标称容量 200Ah，类型 3
Battery|电池采集已启动：/dev/ttyS9，从站 1，轮询 10 秒，上传 60 秒
```

## 5. 协议与数据字段

控制器动态数据从 `0x0100` 开始，一次读取 `0x0100~0x0122` 共 35 个寄存器。

| 地址 | 含义 | 解析 |
| --- | --- | --- |
| `0100H` | 蓄电池 SOC | 低 8 位，0~100% |
| `0101H` | 蓄电池电压 | ×0.1 V |
| `0102H` | 充电电流 | ×0.01 A |
| `0103H` | 控制器温度/蓄电池温度 | 高 8 位控制器，低 8 位电池；b7 符号位 |
| `0104H` | 负载电压 | ×0.1 V |
| `0105H` | 负载电流 | ×0.01 A |
| `0106H` | 负载功率 | W |
| `0107H` | 太阳能板电压 | ×0.1 V |
| `0108H` | 太阳能板电流 | ×0.01 A |
| `0109H` | 充电功率 | W |
| `010AH` | 负载开关 | 0/1 |
| `010BH~0114H` | 当天统计 | 最低/最高电压、最大电流、安时数等 |
| `0115H~0117H` | 运行天数、过放次数、充满次数 | 直接读取 |
| `0118H~011FH` | 累计充电/放电安时、发电/用电量 | 32 位，高字在前 |
| `0120H` | 负载状态/充电状态 | 高字节 b7 开关、b0~b6 亮度；低字节充电模式 |
| `0121H/0122H` | 故障/告警 | 高 16 位/低 16 位 |
| `E002H` | 蓄电池标称容量 | Ah |
| `E004H` | 蓄电池类型 | 0 自定义，1 开口，2 密封，3 胶体，4 锂电池 |

重要限制：

- 协议没有“电池放电电流”寄存器；
- `0x0102` 是充电电流，`0x0105` 是控制器负载电流；
- 如果负载不经过控制器 LOAD 输出，控制器无法准确计算 SOC；
- SOC 由控制器内部算法给出，MiniCollection 只负责读取和显示。

## 6. SOC 校准与判断

### 6.1 先看电压

在设备上读取 `0x0101`，同时用万用表测电池端子电压。

- 两者接近：控制器采样正常；
- 万用表明显更低：检查接线、保险丝、共地；
- 电压很低但 SOC 仍高：控制器 SOC 配置或算法问题。

### 6.2 检查控制器参数

读取：

- `E002` 标称容量；
- `E004` 电池类型；
- `E005~E00E` 过压/充电限制/浮充/过放等阈值。

这些值必须和实际电池匹配。例如 12V 铅酸/胶体：

```text
E005 超压         约 14.4~15.0V
E006 充电限制     约 14.4V
E009 浮充         约 13.8V
E00C 欠压警告     约 12.0V
E00D 过放         约 11.0V
```

如果控制器按 24V/48V 配置，12V 电池的 SOC 会明显不准。

### 6.3 负载接线

如果逆变器/负载直接接电池：

```text
电池 -> 逆变器 -> 负载
```

控制器只能看到电压，看不到放电电流，SOC 会滞后或偏高。  
要准确监控，需要：

- 把负载接到控制器 LOAD 输出；或
- 加分流器/库仑计；或
- 使用带 SOC 的锂电池 BMS。

### 6.4 回退曲线

`ocvCurve` 只在控制器 SOC 无效时使用，不能替代真实放电电流测量。  
12V 铅酸参考：

```text
12.8V=100%，12.6V=80%，12.4V=60%，12.2V=40%，12.0V=20%，11.8V=0%
```

24V/48V 按比例调整。

## 7. 服务器接口

设备上传：

```http
POST /coalmine/devices/{device_id}/sensors
X-Project-Token: <设备上传令牌>
Content-Type: application/json

{"samples":[{"uid":"01-...-battery-main","ts":1720000000000,
  "sensor_type":"battery","sensor_id":"main","quality":"ok",
  "metrics":{"percent":42,"voltage":12.3,"current":2.66,
             "remaining_ah":84,"battery_temp":25}}]}
```

服务端按 `(device_id, uid)` 去重，重复上传不会产生重复历史。

控制台查询：

```text
GET /coalmine/devices/{device_id}/sensors/latest
GET /coalmine/devices/{device_id}/sensors?after_id=0&limit=500
GET /coalmine/devices/{device_id}/sensors?from_ts=...&to_ts=...
```

设备心跳包含：

```json
"sensors": {
  "battery": {
    "ts": 1720000000000,
    "quality": "ok",
    "percent": 42,
    "voltage": 12.3,
    "current": 2.66,
    "load_current": 2.0,
    "battery_temp": 25,
    "has_fault": false
  }
}
```

控制台设备状态页直接读取 `status.sensors.battery`。

## 8. 控制台日志

控制台所有日志都会写入：

```text
<控制台程序目录>/Log/console_YYYY-MM-DD.log
```

配置：

```ini
[Log]
dir=Log
keepDays=30
```

说明：

- `dir` 相对控制台程序目录；
- 默认保留 30 天；
- 电池状态日志格式：

```text
[2026-11-12 09:36:01] [电池] 设备 01：42%  12.3V  充电 2.66A  负载 2.00A  剩余 84.0Ah  电池 25℃
```

- 电池通讯异常：

```text
[2026-11-12 09:36:01] [电池] 设备 01：通讯异常：Modbus 响应超时（从站 1）
```

- 告警：

```text
[2026-11-12 09:36:01] [电池告警] 设备 01：电量低 18%，电压低 11.6V
```

电池日志在数值变化时立即记录，数值稳定时至少每 60 秒记录一次。

## 9. 电池告警

控制台配置：

```ini
[BatteryAlarm]
enabled=1
lowPercent=20
criticalPercent=10
lowVoltage=11.8
criticalVoltage=11.2
repeatMinutes=30
```

说明：

| 配置 | 含义 |
| --- | --- |
| `enabled` | 是否启用电池告警 |
| `lowPercent` | SOC 低告警阈值 |
| `criticalPercent` | SOC 严重告警阈值 |
| `lowVoltage` | 电压低告警阈值 |
| `criticalVoltage` | 电压严重告警阈值 |
| `repeatMinutes` | 同一告警重复提示间隔 |

12V/24V/48V 电压阈值参考：

```text
12V：lowVoltage=11.8，criticalVoltage=11.2
24V：lowVoltage=23.6，criticalVoltage=22.4
48V：lowVoltage=47.2，criticalVoltage=44.8
```

告警级别：

- 通讯异常：`quality != ok`，红色；
- 控制器故障：`has_fault=true`，红色；
- 严重：SOC ≤ criticalPercent 或电压 ≤ criticalVoltage，弹窗 + 托盘；
- 低：SOC ≤ lowPercent 或电压 ≤ lowVoltage，托盘通知 + 任务栏闪烁；
- 恢复：数值回到阈值以上，记录“电池状态恢复正常”。

告警会写入日志，并受 `repeatMinutes` 限制，避免每 30 秒重复弹窗。

## 10. 日常操作

### 10.1 启动前

1. 检查 RS485 A/B/GND 接线；
2. 确认串口存在；
3. 确认 `Config.ini` 中 `port`、`slave`、`baud`；
4. 确认磁盘空间：

```bash
df -h /
```

建议保留至少 1GB。

### 10.2 启动后

```bash
sudo systemctl status minicollection.service --no-pager
grep -i battery /opt/MiniCollection/Log/*.log | tail -20
```

控制台查看：

- 设备在线；
- 电池 SOC/电压/电流；
- 日志目录有 `console_*.log`；
- 无 `[电池告警]` 或已确认告警。

### 10.3 告警处理

1. 查看控制台 `[电池告警]` 和电池数值；
2. 现场测量电池电压；
3. 检查充电是否正常（太阳能/市电）；
4. 检查负载是否过大；
5. 如果电压低但 SOC 高，检查控制器电池类型/容量/电压阈值配置；
6. 如果负载不经过控制器 LOAD，说明 SOC 只能估算，建议加分流器/BMS；
7. 处理后观察告警是否恢复，并记录处理结果。

## 11. 常见问题

### 11.1 控制台提示“电池串口未打开”

检查：

```bash
ls -l /dev/ttyS*
grep -A 15 '^\[Battery\]' /opt/MiniCollection/data/Config.ini
grep -i battery /opt/MiniCollection/Log/*.log | tail -30
```

常见原因：

- `port` 写成了不存在的 `/dev/ttyS1`；
- 配置改了但没重启服务；
- 串口被 `mcu_ctl`/WukongEdge 占用；
- 权限不足（服务不是 root 时）。

### 11.2 偶发“Modbus 响应超时”

检查：

```bash
sudo lsof /dev/ttyS9
sudo fuser -v /dev/ttyS9
```

如果 `mcu_ctl` 和 `MiniCollection` 同时打开同一个串口，就是总线争用。  
处理：

- 禁用 `/etc/init.d/m300_script/S15mcu_ctl`；或
- 给 MiniCollection 换 USB-RS485。

### 11.3 SOC 显示偏高/不变化

优先检查：

- 电池实际电压；
- `E002/E004/E005-E00E` 是否匹配电池；
- 负载是否经过控制器 LOAD；
- `mcu_ctl` 是否导致数据陈旧。

### 11.4 Config.ini 写入失败

检查：

```bash
df -h /
df -i /
ls -l /opt/MiniCollection/data/Config.ini
lsattr /opt/MiniCollection/data/Config.ini
```

最常见原因是磁盘满。清理 `data/bins`、旧日志和 journal 后重试。

### 11.5 data/bins 持续增长

确认：

```ini
[Config]
datacompletion=0
```

并部署支持该开关的程序版本。  
关闭后 `data/bins` 不再生成新文件，事件 mseed 不受影响。

---

## 12. 维护建议

- 控制台日志保留 30 天，定期检查磁盘；
- `data/bins` 如不需要连续原始数据，保持 `datacompletion=0`；
- 事件 mseed 和服务器文件仍需单独保留策略；
- 电池控制器参数变更后，记录 `E002/E004/E005-E00E` 的值；
- 更换电池后重新校准 SOC 和告警阈值；
- 长期运行建议加磁盘空间监控和日志轮转。
